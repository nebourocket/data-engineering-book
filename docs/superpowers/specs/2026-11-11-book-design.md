# データエンジニアの本 — 設計

- 日付: 2026-11-11
- 状態: 設計承認済み (ユーザー 2026-11-11)。仕様書のレビュー待ち

## 1. 目的と成功条件

これからデータエンジニアを目指す人が、ウェブサイトを第1章から順に読み、手を動かせば「一人前のデータエンジニア」として現場で仕事を任されるところまで行ける本を作る。

- **基礎編 (無料・16章)**: これだけで一人前。理論・背景・技術・スキル・キャリアまでを段階的に扱う。
- **応用編 (有料・買い切り 500 円・12章)**: 大規模・本番運用・設計判断を深く掘り下げる。

成功条件 (検証できる形):

1. GitHub Pages で基礎編16章が読め、`mkdocs build --strict` が警告なしで通る。
2. 本文のコード例はすべて `examples/` にあり、Docker (ds) 内でテストが通る。
3. 応用編の本文は公開リポジトリにも公開サイトにも存在しない (公開側に本文の文字列が無いことをテストで確かめる)。
4. Stripe で 500 円を払うとキーが発行され、そのキーで応用編12章が読める。偽造・改ざん・失効したキーでは読めない (Worker のテストで確かめる)。
5. 各章の事実の主張に出典がある (章末の参考文献)。

## 3. 決済とキーの仕組み

PFC の Worker (`~/pfc-calculator/worker/src/index.js`) と同じ方式を土台にする。

### キーの形

`DEB1.<payload>.<署名>` (どちらも base64url)。payload は `{v:1, sid:<Session ID の SHA-256 先頭32桁>, iat:<発行時刻>}`。個人情報は入れない。ECDSA P-256 / SHA-256 で署名する。

### Worker の API

| メソッドとパス | 動き |
| :--- | :--- |
| `GET /license?session_id=cs_…` | Stripe に Checkout Session を問い合わせ、`complete`・`paid`・`jpy`・`500`・この Payment Link 経由の5つがそろえばキーを返す。そろわなければ 402 |
| `GET /chapter/<01〜12>` + `Authorization: Bearer DEB1…` | 署名を公開鍵で確かめ、失効リスト (`revoked:<sid>`) に無ければ KV の `chapter:<id>` を返す。無効なら 401、章が無ければ 404 |
| `OPTIONS` | CORS。`ALLOWED_ORIGIN` (`https://nebourocket.github.io`) だけ許す |

- 秘密は `STRIPE_SECRET_KEY` (Checkout Sessions 読み取りだけの制限付きキー) と `LICENSE_PRIVATE_JWK` の2つで、`wrangler secret` にだけ置く。
- 公開鍵は `wrangler.toml` の vars とサイトの設定の両方に置く (公開してよい)。
- 本文の応答は `Cache-Control: private, no-store`。

### 読者の流れ

1. 応用編の目次で「500円で応用編を買う」を押す → Stripe Payment Link (カードのみ・数量変更なし・プロモコードなし)。
2. 支払い後 `…/advanced/?session_id={CHECKOUT_SESSION_ID}` に戻る。
3. `pro.js` が `/license` でキーを受け取り、localStorage に保存し、画面にキーを表示する (別の端末に貼れるように)。URL から `session_id` を消す。
4. 応用編の各章を開くと、`pro.js` が `/chapter/<id>` から本文 HTML を取り、紹介の下に差し込む。キーが無ければ購入ボタンとキー入力欄を出す。

### 割り切ること

- キーを他人に渡されると読まれる。端末数の制限はしない。大量に漏れたキーは失効リストに入れて止める。
- 返金したキーも失効リストに入れる (手作業で `wrangler kv key put`)。

## 4. 内容 (章立て)

各章は「この章でできるようになること → 背景と理論 → 仕組み → 手を動かす → よくある失敗 → まとめと練習問題 → 参考文献」の順で書く。1章 5,000〜8,000 字程度。ハンズオンは DuckDB・PostgreSQL・Python を Docker で動かし、クラウド料金がかからないようにする。クラウドの話は概念とサービスの対応で説明する。

## 5. 書き方の決まり

- **表**: 本文に手で打たない。`data/tables/<章>-<名前>.csv` に書き、本文には `{{ table("<名前>") }}` と書く。`hooks/tables.py` がビルド時に表へ変える。
- **図**: 構成図や流れは Mermaid (コードから描かれる図)。数値を含むグラフは matplotlib のスクリプトを `examples/` に置き、出力した SVG を使う。
- **数字**: 出典のあるものだけ。章末の参考文献に URL か書名を書く。値の揺れやすい料金・性能の数字は「確認日」を添える。
- **コード**: 本文のコードはすべて `examples/<章>/` に同じものを置き、pytest で動かす。
- **応用編の図**: Mermaid は `<pre class="mermaid">` のまま KV に入れ、本文を差し込んだあとに pro.js が Mermaid (CDN, mermaid@11.4.1) で描く。
- **文体**: `writing-conventions` に従う。平易な日本語で、仕組みを先に説明し、具体例を1つ添える。

## 6. テストと検証

| 対象 | 確かめ方 |
| :--- | :--- |
| サイト | `mkdocs build --strict` (ds 内) |
| 表の hook | pytest (CSV → 表、存在しない名前でビルドが失敗すること) |
| コード例 | pytest (ds 内、DuckDB・PostgreSQL コンテナ) |
| 有料本文の混入 | 非公開リポジトリの各章から一文を取り出し、公開リポジトリとビルド結果に無いことを確かめるスクリプト |
| Worker | Node だけで動くテスト (PFC と同じ形): キー発行の条件5つ、偽造・改ざん・失効キーの拒否、章の配信、CORS |
| 内容 | 各章を事実チェック (出典との照合) と差分レビューにかける |
| 本番前 | Stripe のテスト環境で、購入 → キー → 別ブラウザでキー入力 → 応用編を読む、を通しで行う |

## 7. 公開と運用

- GitHub Actions で main への push ごとに `mkdocs gh-deploy` 相当を実行して Pages に出す。URL は `https://nebourocket.github.io/data-engineering-book/`。
- 応用編を更新したら、非公開リポジトリで `build_kv.py` を実行し、`wrangler kv bulk put` で KV に入れる。
- 手順の正本は `docs/DEPLOY.md` (PFC の DEPLOY.md と同じ形)。

### ユーザーにお願いすること

1. Stripe で商品「データエンジニアの本 応用編 (買い切り)」500 円と Payment Link を作る (Stripe MCP が使えればテスト環境は Claude が作る。本番はユーザーが確認して作る)。
2. 制限付きキーと署名鍵を `wrangler secret put` で登録する (ユーザーのターミナルで)。
3. 特商法ページの問い合わせ先を決める (PFC と同じ表記でよいか)。

## 8. やらないこと

- 端末数の制限、アカウント登録、ログイン機能
- 章ごとのばら売り、サブスクリプション
- 英語版
- コメント欄・フォーラム

## 9. 進め方

1. 骨組み: リポジトリ2つ、MkDocs、表の hook、テストの土台、Worker (テスト環境で通しまで)。
2. 基礎編16章を2〜3章ずつ書き、章ごとに事実チェックとコード例のテスト。
3. 応用編12章を同じように書く。
4. 本番の Stripe に切り替え、通しで確認して公開。

骨組み (1) が終わった時点でサイトを公開し、章は書けたものから順に足していく。
